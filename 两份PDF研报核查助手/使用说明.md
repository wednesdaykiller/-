# 两份 PDF 核查助手（本地试运行版）

## 如何使用

1. 解压整个文件夹。无需覆盖原项目文件。
2. 首次使用可运行“安装运行环境.command”，它使用Python 3.12建立独立环境并安装依赖；现有环境依赖齐全可直接启动。
3. 双击“启动核查助手.command”。浏览器将打开本地地址 http://127.0.0.1:8765 。不要直接双击 static/index.html，它需要本地服务。
4. 左侧选择财务报告PDF，右侧选择同公司的研究报告PDF，点击“开始核查”。
5. 查看状态、指标值及财报依据。点击页码可打开对应PDF。扫描识别待确认时，可在页面核对、填写复核人和依据并确认，系统重新计算结果。
6. 点击“下载报告”。完整数据、原始上传PDF和人工确认记录保存在 runs/任务编号 下，重启后仍可从文件夹打开报告，但当前版本不会恢复页面中的历史任务列表。

若端口占用，可在终端运行 `python3 app.py --port 8767`。终端保持打开，Ctrl+C结束服务。使用同一Python解释器安装和运行，优先Python3.12，避免系统不存在的python命令。

## 国产视觉模型

默认仅本地处理。通过启动环境变量 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL 配置支持图片输入及JSON输出的国产兼容接口，界面才启用“国产视觉模型辅助”。不要将密钥写入项目文件、报告或聊天。

勾选后，系统会发送扫描研报的表格图片至所配置服务商，可能产生费用。模型独立读图，不预先获得OCR数值或财报答案；字段、年份、读数及单位对应后进入规则核查，冲突继续待确认。当前未完成真实模型调用测试，不能据此宣称大模型准确率。

## 自动完成与当前范围

已实现：两PDF上传、公司身份初步匹配、财报原生表格依据提取、研报原生解析/扫描OCR、字段映射、金额单位与期间处理、表格指标对照、证据页码、人工确认留痕、HTML及JSON结果输出。无需标准答案Excel。

财报依据直接来自本次上传PDF；保存字段、期间、原始值、单位、页码及报表口径。可从明确的收入/成本/前期数据派生毛利率和同比并保留公式。区分母公司与合并报表、利润表财务费用与现金流补充资料中的同名项目。自动发现差异仍标为“差异待核实”，不把所有差异直接认定为错误。

仍有边界：
- 当前以中文年报的原生有线表格、明确年度列为主要支持对象。扫描财报不自动生成可信标准，页面会被记录为未覆盖。
- 研报正文尚未全面自动核查；页面明确展示覆盖范围。无表格、无法识别的字段不会算作核查通过。
- EPS、估值指标和模糊统计口径需进一步证据；预测值不直接与历史实绩比较。
- 未配置模型时，OCR表格仍可提取和匹配依据，但不会自动计为相符。
- 财报跨页表格只在相邻页面、列数和报表类型兼容时延续，不继承年度摘要到季度表。
- 公司匹配当前依赖可提取的名称/证券代码，无法识别时停止，不强行比对。

这是一版可运行的任务编排原型，尚不是覆盖任意PDF、完全无人复核的最终比赛版本。

## 已完成验证

使用公牛2024年报（237页）和扫描研报（5页）完成了不使用提取缓存的实际流程，约25秒生成报告（本机单样本，不含人工确认或模型调用）。提取64条财报依据（含重复来源和派生指标），160个规则覆盖的研报表格数值：64项待确认、96项预测值。没有把未经核验的OCR值计为通过。

包内cache只含同一研报的OCR提取结果与质量记录，通过PDF哈希精确匹配，不包含人工标准答案或人工批准决定。使用缓存会在页面注明，不能将缓存耗时当作首次运行耗时。

24项本地测试及脚本语法检查通过。当前执行环境禁止监听本地端口，未完成浏览器交互实测；上传解析、CSRF检查、路径限制及业务逻辑已通过进程内测试。收到本机运行反馈后仍需检查界面布局及浏览器下载行为。

## 可复现命令

在此目录，用已安装依赖的Python执行：

```text
python3 check_pdfs.py 财报.pdf 研报.pdf --out 新结果目录 --no-cache
python3 -m unittest discover -p 'test_agent.py' -v
```

OCR依赖可以安装到独立环境，或通过 OCR_DEPS_PATH 指向已有OCR依赖目录。示例结果在fresh_run中，使用原始提取缓存的对照运行在demo_run中。单元测试中的人工确认操作是测试数据，不会写入用户原项目。
